## Pipeline

```
Input (structured Client State)
   → Requirement
   → Risk
   → Gap (coverage-gap-analysis)
   → Solution
   → Knowledge Search (evidence)
   → Product Candidate Provider
   → Recommendation
   → Report
```

## What the runtime actually does

The orchestrator runs the full 8-stage chain. The upstream three stages
(`client-intake`, `requirement-analysis`, `risk-analysis`) are **seeded from a curated fixture**
(`executor: provided`) — they are not re-generated by a model at runtime. From
`coverage-gap-analysis` onward, **every stage is executed locally, evaluated deterministically,
and checkpointed**.

This is the honest execution boundary of the current portfolio: the runtime is proven from
**Structured Client State** onward. Raw natural-language intake is intentionally outside the
current execution boundary.

## Honest scope note

> **P001 is a fictional demo catalog product, used only for runtime validation.**
> `is_demo = true` is carried on the product, the candidate, the recommendation, and the report.
> It is **not** a real insurance product, premium, or insurer offering.

The point of Demo A is not "here is a product you should buy." It is: *given a structured client
state, the agent can produce a recommendation whose every claim is traceable to a candidate, a
solution, a gap, a risk, a requirement, and ultimately to evidence with `document_id` + `chunk_id`.*
