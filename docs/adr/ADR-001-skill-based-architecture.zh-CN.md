# ADR-001 · 基于技能的架构

<a id="context"></a>
## 背景

保险顾问任务天然可分解为若干判断层：客户事实、需求、风险、保障缺口、解决方案策略、证据、候选产品、推荐方案，以及最终报告。最朴素的做法——用一个庞大的 Prompt / 一个庞大的函数顺序完成所有事情——意味着任何一层发生变更都会撼动整条链路。

<a id="decision"></a>
## 决策

每一层成为一个**独立的 Specialist Skill**，声明：它消费哪些规范产物（Canonical Artifacts）、恰好产出一个规范产物（Canonical Artifact）、以及遵循哪份契约。Skill 之间**从不互相直接调用**；它们只通过产物（Artifacts）协作。

<a id="alternatives"></a>
## 备选方案

- 单体 Prompt（一次性生成所有结论）：没有逐层校验；一次幻觉就会污染整条链路。
- 单体 Python 函数：可测试但不可演进；改动一层就意味着要动整个文件。
- 链式调用的 Skill（A 执行 `import B`）：把依赖固化进代码。

<a id="why"></a>
## 理由

分层使得每一层的正确性可以被**独立地**定义、校验与修复。风险层中的错误不会破坏事实层；改动保障缺口层也无需强制重新训练推荐层。每层一个产物还意味着每次变更都可 diff、可追溯、并在同一样本上可复现。

<a id="trade-offs"></a>
## 取舍

- 需要维护契约层（9 schemas + 适配器）——前期成本更高。
- 层间存在**语义漂移**风险（同一概念被定义两次）——通过“契约作为唯一事实来源 + 规范优先（canonical-first）”来抑制，但仍需持续的纪律约束。
- 一次运行需要更多步骤（磁盘上更多产物），但对于**高风险决策**，可解释性 > 步骤数量。
