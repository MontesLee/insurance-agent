# 年金 / 养老 — 信息采集维度

> Overlay `annuity`（status: draft）。只定义**多问什么**与**怎么记录**，不定义任何判断。
> draft 状态不会被自动激活，需补 Eval 用例后才转 active。

## A. 必填维度（激活且经客户确认后，进入 intake_complete 判定）

| 维度 | 为什么需要 | 记录口径 |
|---|---|---|
| 退休年龄预期 | 领取起始的锚点 | 客户自述年龄或"按法定" |
| 社保参保类型与缴费年限 | 已有养老保障基础 | 客户自述；不预测待遇金额 |
| 养老居住方式意向 | 决定现金流形态 | 居家/社区养老/机构养老/未定 |
| 现有养老储备 | 缺口判断 | 客户自述：社保/企业年金/个人储蓄/商业年金/无 |
| 养老资金首要目标 | 区分现金流与护理储备 | 客户原话，如"每月能多领点"或"怕失能要请护工" |

## B. 建议维度（不阻塞 intake_complete）

| 维度 | 为什么需要 | 记录口径 |
|---|---|---|
| 期望领取起始年龄 | 方案设计输入 | 客户表述 |
| 领取方式偏好 | 同上 | 年领/月领/未定 |
| 是否关注保证领取年限 | 客户顾虑点 | 客户表述 |
| 护理/失能顾虑 | 长期护理需求 | 客户表述（事实，不做健康评价） |
| 长寿家族史（自述） | 客户关注点 | 客户原话 |
| 流动性需求 | 资金安排约束 | 客户表述，如"中途可能要取" |
| 缴费期与年缴预算 | 方案设计输入 | 客户表述 |
| 是否有企业经营/股权 | 资金来源事实 | 客户自述 |

## C. 触发后可一并确认的关联信息

- 当前年龄与配偶年龄（缴费期与领取期的窗口）
- 家庭年结余量级（可投入养老的资金上限）
- 是否已有商业年金或增额终身寿（已有储备去重）

## D. 本险种特有的边界红线

- **禁止预测社保待遇。** 客户问"我退休能领多少" → 说明这属于社保口径，建议向社保部门或单位确认，Intake 不代算。
- **禁止算缺口。** 客户问"要准备多少钱才够养老" → 需结合寿命假设、通胀、支出结构测算，分析环节给依据。
- **禁止预测利率/收益/寿命。** 任何形式的"大概能翻一倍""按 3% 算"都越界。
- **禁止建议缴费金额。**

## E. 常见误判提醒

- 客户说"想给爸妈买养老" → 被保险人可能是父母，采集对象要切换，不要默认记在客户本人名下。
- "养老"与"传承"在增额终身寿上重叠：偏现金流归 annuity，偏资产安排归 inheritance，按客户原话主体意图归类。
- 年轻客户提"养老"可能只是财务焦虑，未必有明确投保意图 —— 先确认再激活。
