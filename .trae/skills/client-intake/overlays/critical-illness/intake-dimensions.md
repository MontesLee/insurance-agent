# 重疾险 — 信息采集维度

> Overlay `critical-illness`。只定义**多问什么**与**怎么记录**，不定义任何判断。
> 通用规则（confirmed/inferred/missing/pending、H1-H6、QID 五态）一律以 `references/` 为准。

## A. 必填维度（激活且经客户确认后，进入 intake_complete 判定）

| 维度 | 为什么需要 | 记录口径 |
|---|---|---|
| 关注重疾的动因 | 决定后续需求分析的切入点 | 客户原话；如"同事得了大病""家里有人得过癌症" |
| 现有重疾保障 | 判断是否有重复或缺口 | 有/无/不清楚；有则记险种名与保额量级（客户自述） |
| 健康告知相关事实（既往疾病/手术/住院史） | 核保必需的事实基础 | **只记客户原话**，不归纳病名、不判断严重程度 |
| 近两年体检异常 | 同上 | 客户自述的异常项名称，原样记录 |
| 目前长期服药情况 | 同上 | 有/无；有则记客户表述，不追问具体药理 |
| 家族病史（父母/兄弟姐妹/子女） | 部分险种健康告知问询项 | 客户自述，记"客户称父亲有高血压"句式 |
| 吸烟情况 | 核保与费率事实 | 从不/已戒（记戒断年份）/每日支数与年限 |
| 职业类别（自述） | 影响可投保产品范围 | 客户自述岗位与是否涉及高空/井下/危化 |

## B. 建议维度（不阻塞 intake_complete）

| 维度 | 为什么需要 | 记录口径 |
|---|---|---|
| 身高体重（BMI 相关） | 部分产品问询 | 客户自述，只记数字 |
| 收入替代预期（若患病希望覆盖几年开支） | 下游测算保额的输入 | 客户表述的年限或"没想过" |
| 是否关注轻症/中症责任 | 形态偏好 | 客户表述；Intake 不解释责任定义 |
| 是否偏好多次赔付 | 形态偏好 | 同上 |
| 是否要求含身故责任 | 形态偏好 | 同上 |
| 缴费期偏好 | 方案设计输入 | 客户表述，如"想 20 年交" |

## C. 触发后可一并确认的关联信息

激活本 overlay 时，顺带确认这些通用信息可避免二次访谈：

- 家庭年收入与主要收入贡献者（重疾保额锚定收入替代）
- 现有负债（房贷/消费贷），康复期支出压力
- 被保险人是本人、配偶还是子女（决定采集对象）

## D. 本险种特有的边界红线

叠在通用层 `references/01-boundary.md` 之上：

- **禁止评价疾病严重程度。** 客户说"甲状腺结节 3 类"，记录为事实，不接"这个不严重""这个可能要除外"。
- **禁止预判核保。** 客户问"我这个能买吗"，标准回复：健康情况我已如实记录，能否投保由保险公司核保决定，我这边不下结论。
- **禁止建议保额。** 客户问"买多少合适"，标准回复：这个要结合收入、负债、康复期开支一起算，等分析环节我给您完整依据。
- **禁止把自述当诊断。** 客户说"好像有点心脏病"，记为 `客户自述：好像有点心脏病`，不得整理为 `confirmed: 心脏病`。

## E. 常见误判提醒

- 客户提到"癌症"不代表只关心重疾 —— 可能是医疗险需求（治疗费用报销）。**先确认关注点再激活**。
- 客户说"我有社保，大病够了" —— 这是客户观点，记为 `confirmed` 的观点事实，**不纠正、不辩论、不科普**（科普越界）。
- 家族病史不等于客户本人风险 —— Intake 只记录事实，不推导风险。
