# 医疗险 — 信息采集维度

> Overlay `medical`。只定义**多问什么**与**怎么记录**，不定义任何判断。

## A. 必填维度（激活且经客户确认后，进入 intake_complete 判定）

| 维度 | 为什么需要 | 记录口径 |
|---|---|---|
| 社保状态 | 决定商业医疗险的衔接方式 | 职工医保/居民医保/新农合/无/不清楚 |
| 现有商业医疗险 | 判断重复投保或缺口 | 有/无/不清楚；有则记客户自述的产品与保额量级 |
| 就医习惯偏好 | 决定门诊/住院/特需的责任范围需求 | 客户自述：公立普通/特需/VIP/私立/境外 |
| 既往住院或手术史 | 核保事实基础 | 只记客户原话，不归纳、不评价 |
| 是否被拒保/延期/除外承保过 | 直接影响可投产品范围 | 是/否；是则记客户表述的原因（原话） |
| 关注的核心场景 | 区分住院报销与门诊需求 | 客户原话，如"主要怕住院花大钱" |

## B. 建议维度（不阻塞 intake_complete）

| 维度 | 为什么需要 | 记录口径 |
|---|---|---|
| 是否关注外购药/院外药 | 高价药报销责任 | 客户表述关注/未提及 |
| 是否关注质子重离子等特定治疗 | 责任范围偏好 | 客户表述 |
| 是否要求门诊责任 | 门诊险与住院险差异 | 客户表述 |
| 免赔额接受度 | 方案设计输入 | 客户表述（"一万以下我自己能承担"） |
| 是否含牙科/孕产/体检 | 责任范围偏好 | 客户表述 |
| 单位是否有补充医疗/团体医疗 | 已有保障去重 | 有/无/不清楚 |
| 续保稳定性关注度 | 客户顾虑点 | 客户表述 |

## C. 触发后可一并确认的关联信息

- 家庭成员是否都需要（本人/配偶/子女/父母分别确认）
- 父母年龄（老年医疗险投保窗口与体况关联）
- 常驻城市（就医网络与医院范围）

## D. 本险种特有的边界红线

- **禁止评价既往症影响。** 客户说"我有糖尿病还能买吗" → 记录事实 + "能否投保由核保决定"，不接"这个大概率被拒"。
- **禁止解释社保政策。** 客户问"社保能报多少" → 说明这属于政策口径，建议向社保部门确认；Intake 不代替解释。
- **禁止预判续保风险。** 客户问"会不会买了明年不给续" → 记录为客户顾虑，不给结论。
- **禁止推荐产品。** 客户点名问某产品 → 走通用层越界话术（见 SKILL.md §Scope）。

## E. 常见误判提醒

- 客户说"我有医保" ≠ 不需要商业医疗险 —— 但 Intake **不纠正、不教育**，只如实记录"客户认为医保足够"这一观点事实。
- "住院"可能是重疾（收入损失）也可能是医疗（费用报销）—— 用 A 类"关注的核心场景"维度区分，不要靠猜。
- 医疗费用与收入损失是两类需求，客户常混着说，按原话分别记入两个 overlay 的事实区。
